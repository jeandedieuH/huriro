# @huriro/cli

`huriro` — the client CLI for humans and coding agents (§13.1a, ADR-0021).
MIT-licensed and publishable: it must stay a pure HTTP client. The server image
ships a separate operator CLI inside `apps/server` (`huriro migrate`, `doctor`,
`backup…`) — same binary name, different package and entrypoint; they never ship
in the same artifact, so there is no conflict.

## Rules

- Zero server imports — cruiser forbids `apps/*`, `packages/db`, `packages/env`.
  Only `@huriro/agent-tools` (manifest types) is allowed.
- `src/generated/commands.ts` is GENERATED by `bun run gen` from the tool
  registry — never hand-edit; `gen:check` must stay green.
- All I/O goes through the `Io` seam in `io.ts` so tests inject fs/fetch/stdio;
  `main(argv, io)` is the only entry (bin.ts wraps it).
- Exit codes are a contract (http.ts `EXIT`): 0 ok, 2 usage, 3 auth, 4
  approval_required, 5 rate-limited, 6 not-found. Do not invent new ones.
- Secrets: tokens live in `credentials.json` (0600, atomic writes); never log
  tokens — use `redactSecret`.
- Refresh-token rotation: persist the NEW refresh token before using the new
  access token.

## Commands

| `bun run gen` / `gen:check` | regenerate `src/generated/commands.ts` |
| `bun run build` | single-file `dist/huriro.js` (Node ≥24 / Bun) |
| `bun run build:binary` | standalone compiled binary |
| `bun test` | unit suite (injected Io, no network) |
